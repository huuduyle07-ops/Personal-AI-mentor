# Personal Accountability AI

[English](README.md) | [한국어](README.ko.md) | [Tiếng Việt](README.vi.md)

2026 SOL-AIM 프로젝트 경진대회를 위한, 로컬 처리를 우선하는 Discord 목표 실천 도우미입니다. 최종 제출 기한은 2026년 12월 2일입니다. 설정된 Discord 사용자 한 명의 매일 반복되는 목표 하나를 관리하며, 사용자가 신청한 경우 한국 표준시(KST)에 맞춰 진행 상황을 확인하는 DM을 보냅니다. 사용자가 보고한 학습 시간과 퀴즈로 확인한 학습 내용을 구분하고, 목표 조정은 사용자의 승인을 받은 뒤 적용합니다.

개인 상태는 SQLite에 저장합니다. Discord 메시지는 Discord를 거치므로 시스템 전체가 오프라인으로 동작하는 것은 아닙니다. 로컬 Ollama를 이용한 조언은 선택 기능이며 기본적으로 비활성화되어 있습니다. 기존 `/setgoal`, `/report`, `/summary` 명령어와 데이터베이스의 기존 레코드를 유지합니다.

## 설치 및 실행

Python 3.11.9 이상과 [uv](https://docs.astral.sh/uv/)가 필요합니다. 저장소 루트에서 PowerShell로 실행합니다.

```powershell
uv sync --locked
Copy-Item .env.example .env
# 로컬에서 .env를 설정한 뒤 실행합니다.
uv run python bot.py
```

기존 `.env`가 있다면 덮어쓰지 마세요. 봇은 연결 전에 설정을 검증합니다. `bot` 모듈을 임포트하는 것만으로는 데이터베이스를 만들거나 `.env`를 읽거나 Discord에 연결하지 않습니다. 데이터베이스 하나당 봇 프로세스 하나를 실행하세요.

기본 uv 캐시 경로의 접근이 제한되어 있다면 작업 폴더 안에 캐시를 지정할 수 있습니다.

```powershell
uv --cache-dir .uv-cache sync --locked
uv --cache-dir .uv-cache run python bot.py
```

## Discord 설정

1. Discord Developer Portal에서 애플리케이션과 봇을 만듭니다. 봇 토큰은 로컬 `.env`에 입력합니다.
2. Discord에서 개발자 모드를 켜고 자신의 사용자 ID를 복사하여 `ALLOWED_USER_ID`에 입력합니다. 개발용 서버를 지정하려면 서버 ID를 `DISCORD_GUILD_ID`에 입력합니다.
3. `bot`, `applications.commands` 범위로 봇을 서버에 설치합니다. 애플리케이션 명령어 사용과 봇 DM을 허용하세요. 관리자 권한은 필요하지 않습니다.
4. 봇을 실행합니다. 서버와 DM에서 사용할 전역 명령어를 동기화하고, 개발용 서버를 지정했다면 해당 서버의 명령어도 동기화합니다. 전역 명령어가 Discord에 표시되기까지 시간이 걸릴 수 있습니다.
5. 모든 명령어는 설정된 사용자 ID를 확인합니다. 예약 체크인은 직접 활성화해야 합니다. Discord가 DM을 차단하면 전송 시도 후 `/checkins action:status`에 `blocked`가 표시됩니다. 다음 예약 시간 전에 DM을 허용하세요.

Message Content, Members, Presence 특권 인텐트는 필요하지 않습니다. 일반 메시지는 모니터링하지 않습니다. 명령어 응답은 실행한 사용자에게만 보이는 비공개 응답(ephemeral)이며, 예약 메시지는 설정된 사용자의 DM으로만 보냅니다. 플랫폼의 상호작용 방식은 [discord.py 상호작용 API 문서](https://discordpy.readthedocs.io/en/stable/interactions/api.html)를 참고하세요.

## 명령어 및 시연

실제 개인정보 대신 가상의 한국어 학습 목표로 시연할 수 있습니다. 슬래시 명령어의 옵션 이름은 Discord에 표시되는 영문 이름 그대로 사용합니다.

1. `/setgoal title:Korean minutes:30`으로 하루 30분 목표를 설정합니다.
2. `/checkins action:enable midday:12:00 evening:21:00`으로 KST 기준 체크인을 활성화합니다. 빠르게 시연하려면 `midday`를 현재보다 몇 분 뒤로, `evening`을 그 이후로 설정하세요. 봇을 실행한 상태로 DM을 기다립니다.
3. `/report minutes:30`으로 오늘의 **누적 총 학습 시간**을 보고합니다. 현재 총합은 새 값으로 대체하지만 이전 보고 이벤트는 모두 보존합니다. 여러 번 보고해도 각 값이 합산되지는 않습니다.
4. `/quiz`로 미리 정의된 한국어 어휘 문제를 받습니다. 안내에 따라 `/answer attempt:<id> answer:<answer>`로 답합니다. 시연 문제는 ‘물’의 영어 뜻을 묻고, 정답은 `water`입니다.
5. 먼저 오답을 입력하면 `review_required`가 됩니다. 다시 `/quiz`를 실행해 정답을 입력하면 `passed_after_support`가 됩니다. 첫 시도에 정답을 입력하면 `verified`가 됩니다. 이 상태는 시험한 어휘와 현재 보고 버전에만 적용되며, 30분 동안 공부했다는 사실을 독립적으로 증명하지 않습니다. 학습 시간을 새로 보고하면 검증 상태는 `reported`부터 시작합니다.
6. `/recover reason:Unexpected work shift`로 예상치 못한 근무 등 장애 요인을 알립니다. 봇은 오늘 목표를 절반으로 줄이는 안을 제시하지만, 아직 목표를 바꾸지는 않습니다.
7. `/adjust proposal:<id> decision:approve`로 승인하면 오늘 계획에만 조정을 적용합니다. `reject` 또는 `cancel`을 선택하면 목표는 유지됩니다. 원래의 하루 30분 반복 목표와 최초 일일 목표 기록도 보존됩니다. 다음 날에는 반복 목표를 다시 적용합니다.
8. `/summary`에서 최초 목표, 현재 적용된 목표, 보고한 시간, 퀴즈 결과, 장애 요인을 확인합니다. 저녁 DM에도 같은 형식의 리뷰를 보냅니다.
9. 봇을 종료했다가 다시 실행하고 `/summary`, `/history`, `/checkins action:status`를 확인합니다. 상태는 유지되며, 이미 전송 처리를 시작한 당일 체크인 시간대에는 중복 전송하지 않습니다.
10. `/checkins action:pause`, `/checkins action:resume`, `/checkins action:disable`로 알림을 일시 중지하거나 재개하거나 비활성화합니다. `/ask text:<question>`으로 선택적인 로컬 AI 조언을 요청할 수 있습니다. `/ask ... non_urgent:true`는 모델을 호출하지 않고 `DEFER` 라우팅 결정을 기록합니다. 나중에 논의하고 싶을 때 질문을 직접 다시 보내세요.

## 구조 및 데이터 저장

| 모듈 | 역할 |
|---|---|
| `core.py` | 기존 GoalStore API, 일일 계획 스냅샷, 보고 버전 기록, 일일 리뷰 |
| `memory.py` | 트랜잭션 기반 SQLite 마이그레이션, 추가 전용 이벤트 기록, 조건별 이력 조회 |
| `bot.py` | 사용자 권한을 확인하는 슬래시 명령어, 비공개 응답, DM 어댑터, 백그라운드 루프 |
| `scheduler.py` | 체크인 신청 설정, 일일 예약 상태 저장, 재시작 복구, 전송 결과 기록 |
| `verification.py` | 미리 정의된 어휘 문제와 검증 시도 이력 보존 |
| `recovery.py` | 규칙 기반 일일 조정 제안, 승인·거절·취소의 원자적 처리 |
| `router.py` | 교체 가능한 Router 인터페이스, RULE/CLARIFY/LLM/DEFER 규칙, 결정 감사 기록 |
| `llm_adapter.py` | 시간·크기가 제한된 로컬 HTTP 추론, 엄격한 JSON 조언 검증, 실패 시 기본 응답 |
| `config.py`, `time_utils.py` | 환경 설정 검증, 날짜·학습 시간·KST 시각 처리 |
| `experiments/router/` | 운영 코드와 분리된 합성 데이터셋, 기준 모델 학습, 평가 파이프라인 |

SQLite의 `PRAGMA user_version`을 이용해 마이그레이션 버전을 관리합니다. 마이그레이션은 트랜잭션 안에서 실행되며 기존 레코드를 삭제하지 않고 테이블을 추가합니다. 기존 `goals`, `reports` 테이블과의 호환성을 유지합니다. 기존 보고 레코드를 바탕으로 보고 버전과 일일 스냅샷을 채웁니다. 과거 보고의 생성 시각은 알 수 없는 값으로 표시합니다. 저장되지 않았던 과거 목표 변경은 복원할 수 없으므로, 마이그레이션 시에는 기존 목표 값을 사용합니다. 업그레이드 전에는 봇을 종료한 상태에서 데이터베이스를 백업하고, `.db` 파일을 외부에 공개하지 마세요.

`summary()['status']`는 기존과 같이 활동 보고 여부(`not_reported` 또는 `reported`)를 나타냅니다. `verification_state`는 별도로 다섯 가지 검증 상태를 제공합니다. 새 보고나 새 퀴즈 시도가 생겨도 이전 퀴즈 기록은 데이터베이스에 남습니다. 계획이 바뀐 뒤에는 오래된 조정 제안을 승인할 수 없으며, 조정을 승인하려면 해당 날짜에 사용자가 명시적으로 명령어를 실행해야 합니다. `Memory(store).history(user_id, day=None, kind=None, limit=20)`으로 관련 이벤트를 최신순으로 조회할 수 있으며, 각 이벤트에는 정보 출처와 타임스탬프가 포함됩니다.

## 스케줄러의 신뢰성 및 동작 범위

- Discord 연결이 준비된 뒤 30초마다 예약을 확인합니다. 체크인을 신청하지 않으면 예약 DM을 보내지 않습니다.
- `(user_id, KST 날짜, 시간대 슬롯)`의 고유한 전송 처리 기록으로 중복을 방지합니다. 동시에 예약 확인이 실행되거나 봇이 재시작되어도 같은 일일 슬롯을 다시 처리하지 않습니다.
- 재시작 시 오늘의 예약 중 예정 시각으로부터 6시간 이내인 건을 처리할 수 있습니다. 지난 날짜의 예약과 활성화·재설정·재개 이전에 지난 시간대는 건너뜁니다. 밀린 알림을 한꺼번에 보내지 않습니다.
- Discord에 보내기 전에 전송 처리를 시작했다는 기록을 먼저 커밋합니다. 프로세스가 비정상 종료되면 실제 전송 여부가 불확실할 수 있습니다. 처리 중인 채 2분 넘게 남은 기록은 `unknown`으로 바꾸고 자동 재전송하지 않습니다. 따라서 DM 중복은 줄이지만 모든 DM의 도착을 보장하지는 않습니다. Discord와 SQLite에 걸친 정확히 한 번 전송은 보장하지 않습니다.
- 전송되지 않았음이 확실하고 재시도가 가능한 오류는 최소 5분 간격으로 최대 3회 시도합니다. 수신 권한이 없거나 수신자가 없으면 `blocked`로 기록합니다. Discord HTTP 오류, 시간 초과 등 결과가 불확실한 경우에는 `unknown`으로 기록하고 자동 재시도하지 않습니다.
- 일시 중지나 비활성화는 새로운 전송 처리의 시작을 막습니다. 이미 진행 중인 전송은 완료될 수 있습니다. 시간을 바꾸더라도 그날 이미 전송 처리를 시작한 슬롯을 다시 열지 않습니다. 재활성화와 재개는 앞으로 도래할 예약 시간부터 적용됩니다.
- 응답이 없거나 전송이 실패했다는 이유만으로 사용자가 미루고 있다거나, 거짓말을 했다거나, 목표 달성에 실패했다고 판단하지 않습니다.

## 선택 기능: 로컬 Ollama 조언

Ollama와 사용할 로컬 모델을 별도로 설치하고 `OLLAMA_ENABLED=true`로 설정한 뒤 `/ask`를 사용하세요. 어댑터는 스트리밍을 끄고 명시적인 JSON 스키마와 함께 [`POST /api/generate`](https://docs.ollama.com/api/generate)를 호출합니다. 요청 전체의 시간 제한과 응답 크기 제한을 적용하며, 리다이렉트와 환경 변수의 프록시 사용을 비활성화합니다. 루프백 주소만 허용합니다.

출력에는 허용된 동작(`SUGGEST` 또는 `ASK_FOLLOWUP`)과 짧은 메시지만 포함되어야 합니다. 조언은 모델의 제안임을 표시합니다. 모델 출력을 실행하는 기능은 없으며, 목표·일정·개인정보 설정·파일을 바꾸거나 명령을 실행할 수 없습니다. JSON 검증이 조언의 사실성이나 적절성을 보장하는 것은 아닙니다. 호출 실패, 시간 초과, 잘못된 JSON, 비활성화된 백엔드에는 규칙 기반의 기본 후속 응답을 제공합니다. 기본 목표 추적과 스케줄링에는 Ollama가 필요하지 않습니다. 조언 본문과 원본 프롬프트는 저장하지 않으며, 호출 결과와 지연 시간만 기록합니다.

```powershell
uv run --extra research python -m pytest -q
```

테스트는 합성 데이터를 담은 임시 SQLite 데이터베이스를 사용하고 Discord와 Ollama를 모의 객체로 대체합니다. 토큰, 실행 중인 봇, 로컬 모델, 외부 서비스가 필요하지 않습니다. `research` 추가 의존성을 설치하지 않으면 모델 평가 테스트는 건너뜁니다. 기존 핵심 테스트 3개도 포함되어 있습니다. 마이그레이션, 영속성, 잘못된 입력, 모든 명령어의 사용자 권한 확인, 예약 재시도·중복 방지·재시작·일시 중지, 검증 상태 전이, 오래된 제안의 승인 차단, 전체 명령어 흐름을 검증합니다.

## 오프라인 모델 실험

```powershell
uv sync --locked --extra research
uv run --extra research python -m experiments.router.run --seed 42
# 출력 폴더와 데이터셋 크기를 선택할 수 있습니다.
uv run --extra research python -m experiments.router.run --seed 42 --samples-per-family 20 --output experiments/router/artifacts
```

의존성을 설치한 뒤에는 네트워크 없이 실험을 실행할 수 있습니다. 합성 학습·검증·테스트 데이터를 JSONL로 저장하고, `baseline.joblib`과 `metrics.json`을 생성합니다. 지표에는 클래스별 정밀도·재현율·F1, 혼동 행렬, 단일 입력 추론 지연 시간의 중앙값과 p95, 모델 파일 크기, 학습 시간, 제한적인 Python 메모리 할당 측정값이 포함됩니다. 직접 생성한 신뢰할 수 있는 joblib 파일만 로드하세요.

기본 분할은 서로 겹치지 않는 시나리오 템플릿 계열을 기준으로 학습 240개, 검증 80개, 테스트 160개입니다. 하이퍼파라미터는 검증 데이터만으로 선택합니다. 두 라우터에는 동일한 텍스트와 명시적 메타데이터를 제공하며, 템플릿 계열 식별자와 정답 라벨은 모델 입력 특성에서 제외합니다. 자세한 내용은 [실험 절차 및 결과](experiments/router/README.md)를 참고하세요. 평가한 기준 모델은 실행 중인 봇에 적용하지 않습니다.

## 구현 완료 항목, 실험 및 향후 계획

완료된 MVP 기능은 기존 명령어, 영속적인 진행 보고, 신청 기반 KST DM 체크인, 일시 중지와 재개, 일일 리뷰, 어휘 검증, 승인 후 적용하는 일일 목표 조정, 이력 조회, 규칙 기반 라우팅, 실패 시 기본 응답을 제공하는 선택적 로컬 조언입니다.

완료된 연구 기반은 합성 데이터 생성, 시나리오 계열별 분리, TF-IDF와 로지스틱 회귀 학습, 모델 저장·재로딩, 분류 지표, 혼동 행렬, 규칙 라우터와의 비교입니다. 합성 데이터의 결과는 해당 라우팅 데이터셋에 대한 평가이며, 실제 사용자의 목표 실천에 효과가 있다는 근거는 아닙니다.

향후에는 검토된 라우팅 시나리오와 메타데이터 특성을 다양화하고, 시간에 따른 상태 변화를 다루는 시뮬레이터와 시퀀스 입출력 규약을 정의한 뒤 LSTM 또는 Mamba를 비교할 계획입니다. 그 이후에야 타당한 학습 목표를 갖춘 지식 증류나 크리틱 모델을 검토합니다. LSTM, Mamba, 크리틱, 지식 증류 모델은 아직 학습하거나 평가하지 않았습니다. 임베딩, 벡터 검색, 클라우드 추론, iOS 모니터링, 범용 우선순위·지연 작업 큐, 공개 배포는 이번 MVP의 범위에 포함되지 않습니다. 현재 `DEFER`는 수동으로 논의를 미루라는 결정이며, 지연 추론을 자동 처리하는 워커는 없습니다.

개인정보 보호의 한계도 있습니다. SQLite는 암호화되어 있지 않으며 개인정보 보존 기간을 자동 관리하거나 삭제하는 UI는 없습니다. 로컬 파일시스템에 접근할 수 있으면 데이터를 읽을 수 있습니다. 외부로 전송한 메시지는 Discord가 보유합니다. 한 명의 사용자만 허용하는 권한 검사는 Discord 연동 계층에서 수행하며, 도메인 라이브러리는 신뢰할 수 있는 로컬 호출자를 전제로 합니다. 비공개 대화를 학습용으로 자동 수집하지 않습니다. 로그에는 메시지 본문, 개인 레코드, 토큰을 남기지 않습니다. 비밀 값, 데이터베이스, 캐시, 실험 산출물은 Git 추적에서 제외합니다. 이 도우미는 건강 상태를 진단하거나 응답 속도로 사용자의 의도를 추정하지 않습니다.

기존 아키텍처 제안은 [한국어 연구 로드맵](docs/RESEARCH_ROADMAP.ko.md)과 [영문 원본](docs/RESEARCH_ROADMAP.md)에서 확인할 수 있습니다. 이 문서들은 이미 구현된 기능이 아닌 향후 아이디어를 설명합니다. 구현 및 검증 기록은 [docs/IMPLEMENTATION_LOG.md](docs/IMPLEMENTATION_LOG.md)에서 확인할 수 있습니다.
